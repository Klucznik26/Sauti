# uniDRC (MPEG-D DRC, ISO/IEC 23003-4) for USAC: plan and measurements

Status (2026-11-24): stage U1 (parsers) DONE: `sauti_unidrc.{c,h}` parse UniDrcConfig (v0 and the V1 extension), LoudnessInfoSet and UniDrcGain; `make test-unidrc` on the real stream `tests/data/usac_d1.{asc,aus,m4a}` (libxaac `-drc:1`): config (3 gain sets, 2 instructions), loudness -16 LUFS, all 34 gain payloads consumed to their padding byte, set 2 around -8 dB.  The loudness values of the libxaac-made fixtures (`nodrc` -11.75 LUFS, `usac_x3` -16.25 LUFS) give EXACTLY the constant gains FDK applies (-24 - L = -12.25 / -7.75 dB; measured -12.2 / -7.7).  Stage U3 (gain curve, `sauti_unidrc_curve`) DONE and checked: applied to our decode of the stream it matches libxaac's DRC output at 73 dB (limited by its 16 bit output; the gain curves themselves are IDENTICAL to libxaac's internal ones: mean |dB difference| 0.0, and `out = in x gain` holds exactly in an instrumented libxaac, 87.6 dB); against FDK 35 dB with a constant normalisation scale fitted (FDK's own DRC differs somewhere, open).  The TIMING (measured in the instrumented libxaac, `DRC_TRACE_IO` / `DRC_TRACE_GAIN`): the gain of a frame is final only after the NEXT access unit, because a frame whose last node is before its end (frame_end_flag 0, e.g. last node 2015) continues with the first segment of the next frame, which starts at that node; the PCM that access unit N produces is multiplied by the gains of access unit N - 1 completed by N (the first call returns unity).  Selection and the options are NOT implemented (U2, U4, U5).  The decision of the owner (2026-11-24): do it as an OPTIONAL OUTPUT FEATURE; the default PCM stays untouched (the reference decoders do not apply it by default either, see below).

## What the references do (measured)

* Encoder: libxaac `xaacenc -aot:42 -usac:1 -drc:1` reads `impd_drc_config_params.txt` from the WORKING DIRECTORY (copy of `test/encoder/impd_drc_config_params.txt`; without the file the option is silently dropped) and writes a `uniDrcConfig` (3 gain sets, all single band: effects 0x0001, 0x0800, 0x0800), a `loudnessInfoSet` (`method_value` -16 LUFS) into the `UsacConfig` extension and `uniDrcGain()` into every access unit (extension element).  The stream grows by about 1.1 kB for 1.5 s.
* Decoder: libxaac `xaacdec` output of that stream is IDENTICAL to the decode of the same stream without DRC (RMS 5912) as long as no DRC option is given (also with `-loudness_leveling_flag` 0 / 1).  With ANY of `-target_loudness`, `-effect` the DRC is applied: `-target_loudness:-24` gives a TIME-VARYING gain (ratio of the outputs 0.36 .. 0.49, median -8.1 dB: the static loudness normalisation -16 -> -24 LUFS = -8 dB plus the dynamic range gains of the selected DRC set), `-effect:1` -11.7 dB RMS.
* So the minimum useful feature is the whole chain: parse -> selection (target loudness, effect request, downmix id) -> gain decoding (nodes, splines) -> gain application (time domain for single band sets; QMF / filter bank for multi band) -> peak limiter.  A "loudness only" shortcut would NOT match the reference.

## Notes for U1 (read from libxaac `drc_src`, 2026-11-24; line numbers of `impd_drc_static_payload.c` unless stated)

* The DRC of the libxaac encoder lives in the V1 EXTENSION of `uniDrcConfig` (the file has `drc_coefficients_uni_drc_count:0` and `drc_coefficients_uni_drc_count_v1:1`, 3 gain sets): `impd_parse_drc_config` (1143) -> `drc_config_ext` (911) -> `UNIDRCCONFEXT_V1` -> `impd_parse_drc_ext_v1` (`impd_drc_dynamic_payload.c` 543): downmix instructions v1, `drcCoefficientsUniDrc` v1 (`impd_drc_parse_coeff` 1681; version 1 adds split characteristics and shape filters, which the encoder does not use), `drcInstructionsUniDrc` v1 (2050), loudEq, EQ.  Extensions are sized (`bitSizeLen`, `bitSize`), so unsupported ones (parametric DRC, EQ, loudness EQ) can be skipped by size, but a V1 payload must be parsed because it holds the DRC sets.
* `UniDrcConfig()`: sampleRatePresent (1) [+ 18 bits, rate - 1000], downmixInstructionsCount (7), drcDescriptionBasicPresent (1) [coefficientsBasicCount (3), instructionsBasicCount (4)], drcCoefficientsUniDrcCount (3), drcInstructionsUniDrcCount (6), channelLayout (baseChannelCount 7, layoutSignalingPresent 1 [definedLayout 8, speakerPosition 7 each when 0]), the downmix instructions (23 bits + coefficients 4 bits each in v0, bsDownmixOffset 4 + 5 bits each in v1), basic coefficients (11 bits) and instructions, coefficients, instructions, configExtPresent (1).
* `LoudnessInfoSet()` (1306): albumCount (6), infoCount (6), each `loudnessInfo` (2436): drcSetId 6 [eqSetId 6 in v1], downmixId 7, samplePeakLevelPresent 1 [12], truePeakLevelPresent 1 [12 + 6], measurementCount 4, each: methodDefinition 4, methodValue (8 / 5 / 2 bits by definition, `impd_dec_method_value` 1254), measurementSystem 4, reliability 2; extension by size.  Loudness of the test stream: `method_def` 1 (program loudness), -16.0 LUFS.
* Where it sits in USAC: the config in the `UsacExtElementConfig` of `ID_EXT_ELE_UNI_DRC`, the loudness info in `UsacConfigExtension` type 2, the gains in an `ID_EXT_ELE_UNI_DRC` element of every access unit (`uniDrcGain()`, `impd_drc_dynamic_payload.c`).  Still to read: the gain sequence syntax (delta time Huffman tables depend on `timeDeltaMin` and the frame size: `impd_init_tbls`, `impd_drc_rom.c`), and how libxaac's `ixheaacd_init_config.c` / `ixheaacd_ext_ch_ele.c` hand the payload over.

## Notes for U1, part 2: transport and `uniDrcGain()` (read 2026-11-24)

* Transport in USAC (libxaac `ixheaacd_init_config.c`, `ixheaacd_config.h`): `ID_EXT_ELE_UNI_DRC` = 4: the `UsacExtElementConfig` of this type carries `usacExtElementConfigLength` bytes = `UniDrcConfig()` (byte aligned); `UsacConfigExtension` type `ID_CONFIG_EXT_LOUDNESS_INFO` = 2 carries `LoudnessInfoSet()`; every access unit has an extension element of type 4 whose payload is `UniDrcGain()`.  The DRC frame size is the codec frame (1024 output samples at ccfl 1024, 2048 / 4096 with eSBR 4:1: the OUTPUT frame length), `deltaTminDefault` = the smallest power of two above `0.5 + 0.0005 * sampleRate` (`impd_get_delta_tmin`: 32 at 48 kHz), `numGainValuesMaxDefault = frameSize / deltaTminDefault`.
* `UniDrcGain()` = for every gain sequence of the FIRST `drcCoefficientsUniDrc`: profile CONSTANT: nothing (one node, gain 0 dB); otherwise `DrcGainSequence` = `SplineNodes`: `drcGainCodingMode` (1): 0 = one node (initial gain, node time frameSize + timeOffset); 1 = `slopes` (unary node count: one bit per node, last = 1; with spline interpolation each node a slope code of the 15 entry table, linear = slope 0), `times` (when `fullFrame` is 0 a frame-end flag first; delta time codes: the table is GENERATED from `numGainMaxValues` (`impd_gen_delta_time_code_tbl`: 2 bits '00' = 1, '01xx' = 2..5, '10xxx'... see the function; escape `2 + Z` bits), node time = previous + delta * timeDeltaMin; nodes beyond the frame go to the next frame's reservoir), `gains` (initial gain by profile: REGULAR sign + 8 bits * 0.125 dB, FADING sign [+10 bits], CLIPPING sign [+8 bits]; then delta gain codes, 25 entry table for profiles 0 / 1, 49 entries for profile 2); `timeOffset` = -1 without time alignment, else `-deltaTmin + (deltaTmin - 1) / 2`.  After the sequences: `uniDrcGainExtPresent` (1) + extensions (type 4 bits, size len 3 bits + 4).
* ROM to carry over as data (libxaac `impd_drc_rom.c`, Apache 2.0, register entry needed): `ia_drc_gain_tbls_prof_0_1` (25 entries), `ia_drc_gain_tbls_prof_2` (49), `slope_code_tbl_entries_by_size` (15), downmix coefficient tables `dwnmix_coeff` (16) / `dwnmix_coeff_lfe` (16) / v1 table, DRC characteristic tables for the selection.  The delta TIME table is a formula.
* Still unread: the selection process (`impd_drc_selection_process*.c`, 3 files, 3200 lines: what a decoder with a given target loudness / effect request picks), gain interpolation and application (`impd_drc_gain_dec.c`, `impd_drc_process.c`, `impd_drc_main_td_process.c`), the peak limiter, the way libxaac sets the DRC frame size for USAC with SBR.

## Selection and loudness: what libxaac really does on the test stream (instrumented build, 2026-11-24)

Instrumented copy of libxaac (`~/tmp_ayo/xaacdbg/src`, env `DRC_TRACE=1` prints the result of `impd_drc_uni_sel_proc_process` in `impd_drc_selection_process.c`; the repository copy `~/Sauti-tools/libxaac` is untouched).  Stream: `drc.es` (3 DRC sets with effects 0x0001, 0x0800, 0x0800, loudness info -16 LUFS, set ids 1, 2, 3 in the file).

| xaacdec options | selected sets | `loudness_normalization_gain_db` | PCM |
|---|---|---|---|
| none | no selection runs (DRC off) | - | unchanged |
| `-target_loudness:-24` / `-16` / `-31` | 1 set, id 2 | 0.0 | identical in all three: -8.1 dB median, time varying |
| `-effect:1` | 2 sets, ids 2 and 1 | 0.0 | -11.7 dB RMS |
| `-effect:2`, `-effect:3` | 1 set, id 2 | 0.0 | as the default |

* So in `xaacdec` (the stock test bench) the target loudness value has NO effect on the stream: loudness normalisation is not applied (the selection reports 0 dB); what changes the PCM is only the DYNAMIC gain of the selected DRC set.  The "-8 dB" is the gain sequence of set 2, not the -16 -> -24 LUFS normalisation.  Implementing the selection faithfully (3 200 lines) is not needed to reproduce this stream: U2 can start as a SIMPLIFIED selection (the set the reference picks for the default request: no downmix, no EQ, no complexity limit) and be extended by the traces above, checking each rule against this instrumented decoder.
* The decoder only runs the DRC after any of these options is set (the API flag `drc_enable` is set by them).

## The second reference: FDK applies it BY DEFAULT (measured 2026-11-24, `sauti_fdk_raw_oracle` against libfdk-aac 2.0.3, 32 bit, no options)

* On the streams with DRC (`drc.es`) FDK's output follows the SAME time varying gain as libxaac with DRC on: block RMS ratio to our unprocessed decode 0.374 / 0.372 / 0.408 / 0.478 / 0.454 / 0.392 ... against libxaac 0.372 / 0.369 / 0.412 / 0.483 / 0.449 / 0.384 ...  (both agree to about 1 %).  So the DRC of the selected set is applied by both; FDK without being asked.
* On the streams WITHOUT any DRC data (libxaac encoder without `-drc`, e.g. `nodrc.es`, `tests/data/usac_x3.m4a`) FDK's output is a CONSTANT gain times our decode (correlation 1.000001): -12.2 dB (`nodrc`), -7.7 dB (`usac_x3`).  The libxaac encoder measures the program loudness itself and always writes a `loudnessInfoSet` (`ixheaace_loudness_measurement`); FDK normalises to its default target of -24 LUFS (nodrc: measured about -11.8 LUFS, x3: about -16.3 LUFS).  libxaac's decoder (stock options) does not normalise, our decoder does not either: the FDK comparisons of the other USAC fixtures in this repository are therefore made after removing a constant gain (their SNR figures stay valid).
* Consequence for the plan: FDK is the reference for the NORMALISATION (every libxaac-made fixture is a free test: gain = target - measured loudness, constant), libxaac for the dynamic gains and the selection (instrumented copy).  Both must agree on the stream with DRC data (they do to about 1 %).  Our default output stays as it is (equal to libxaac's default and to FDK without its normalisation); the feature is an option.
